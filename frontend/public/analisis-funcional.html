Sistema MedCloud — Gestión Médica Integral

Analista de Sistemas Senior Clientes y Gerencia de Clínicas 15 de Junio de 2026

MedCloud es una solución integral de software médico y financiero de vanguardia, diseñada para optimizar los flujos operativos en clínicas y consultorios privados. El sistema está estructurado bajo un enfoque multiusuario con segregación de funciones, garantizando un control estricto sobre la agenda de citas, la confidencialidad de las historias clínicas de los pacientes, el flujo de dinero en efectivo en el centro de salud y la distribución automática de honorarios médicos.

Este documento detalla el comportamiento funcional del sistema de una manera accesible para perfiles directivos y clientes interesados en contratar el servicio, explicando los procesos clave, los flujos de información, las reglas de negocio y las excepciones de control.

2. Razones Clave para Contratar MedCloud

Cinco pilares de valor comercial que justifican y aceleran la adopción

Para una administración médica y financiera sin fisuras, MedCloud ofrece cinco pilares indispensables:

Control de Caja en Tiempo Real

Evita discrepancias mediante un proceso rígido de apertura y cierre de caja. El sistema calcula dinámicamente el dinero esperado y obliga al personal a rendir cuentas ante cualquier desvío físico.

Distribución Automática de Honorarios

Automatiza el cobro médico basándose en acuerdos porcentuales de retención por profesional. Al momento del pago, el sistema congela la tasa acordada, garantizando liquidaciones transparentes.

Recordatorios Automatizados

Reduce el absentismo de pacientes mediante notificaciones automáticas previas a la cita y mantiene informados a los profesionales enviándoles su agenda del día siguiente.

Ficha Médica con Alertas Críticas

Permite visualizar alergias y condiciones críticas resaltadas en rojo en la ficha del paciente para prevenir negligencias médicas graves.

Estricta Seguridad y Confidencialidad

Estructura de accesos blindada mediante roles de usuario. El personal administrativo gestiona la agenda y la cobranza sin tener acceso a los diagnósticos o evolución clínica del paciente, mientras que los médicos disponen de un entorno privado de diagnóstico y prescripción.

3. Modelo de Licencia y Periodo de Prueba (Trial)

Ciclo de vida de la licencia, mecanismo de bloqueo y proceso de activación

MedCloud ofrece una modalidad de demostración funcional inicial (Trial de 15 días) para que los centros médicos evalúen el producto de forma directa y práctica.

3.1. Funcionamiento del Trial

  • Al dar de alta el entorno por primera vez, el sistema se inicializa en modo Trial (configurado en la tabla configuracion_trial con es_trial = 1).
  • Cada vez que un usuario inicia sesión, el sistema calcula la diferencia entre la fecha de inicio del Trial más la cantidad de días permitidos (15 días) respecto al día actual, obteniendo la propiedad computada trial_dias_restantes.

3.2. Mecanismo de Bloqueo por Expiración

Para proteger los datos de alteraciones sin licencia pero permitiendo que el cliente consulte su información histórica, el sistema implementa un bloqueo de seguridad en dos niveles:

1
Bloqueo en el Servidor (Backend): El componente de seguridad intercepta todas las solicitudes del sistema. Si los días restantes son inferiores a 0 (vencido), bloquea de inmediato cualquier acción de escritura (crear, editar o eliminar) enviando el error 403 TRIAL_EXPIRED, permitiendo únicamente consultas de lectura.
2
Bloqueo de Interfaz de Usuario (Frontend): Si el trial ha expirado, el sistema oculta los controles normales y despliega un panel de bloqueo absoluto. Este panel impide al operador navegar por las pestañas normales y ofrece un botón de contacto directo para la activación.

3.3. Proceso de Alta y Activación de la Licencia

1
El cliente hace clic en el botón "Activar Licencia" que figura en los banners de aviso del sistema o en la pantalla de bloqueo.
2
Esto abre de forma directa un chat de soporte por WhatsApp con un mensaje preconfigurado (ej: "Hola! Terminó mi periodo de prueba de MedCloud y quiero activar mi licencia").
3
Una vez verificado el pago de la licencia, el equipo de soporte técnico ejecuta una actualización rápida en la base de datos (actualizando es_trial = 0 en la tabla configuracion_trial).
4
Resultado: El sistema se activa de inmediato para todos los usuarios del centro médico de forma transparente, eliminando los avisos del trial y desbloqueando permanentemente las funciones de registro de información.

4. Programador de Recordatorios y Agendas Automáticas

Módulo de automatización que ejecuta tareas en segundo plano cada 10 minutos

4.1. Recordatorio de Turnos a Pacientes

Destinatario: Pacientes Ciclo: Cada 10 minutos

Objetivo: Asegurar que los pacientes asistan a sus turnos del día siguiente.

1
El sistema consulta la base de datos buscando todos los turnos del día de mañana en estado Pendiente o Confirmado con recordatorio_dia_anterior_enviado = 0.
2
Para cada turno encontrado, extrae la dirección de email registrada del paciente.
3
Despacha un correo electrónico personalizado con: Nombre del Paciente, Fecha y Hora del Turno, Nombre del Médico y Especialidad.
4
Una vez enviado con éxito, actualiza el estado del turno asignándole recordatorio_dia_anterior_enviado = 1 para prevenir el envío duplicado.
5
Caso especial: Si el paciente no posee un correo electrónico válido, el sistema lo marca automáticamente como procesado para evitar bucles repetitivos.

4.2. Aviso a Médicos de su Agenda de Mañana

Destinatario: Médicos Ejecución: 20:00 hs diarias

Objetivo: Notificar a cada profesional cuántos pacientes atenderá mañana y enviarle su grilla de turnos.

1
El programador evalúa la hora del servidor. Si es la ventana horaria de las 20:00 hs, inicia el proceso de aviso.
2
Consulta qué médicos tienen turnos programados para el día siguiente y verifica que no se les haya enviado ya la agenda de esa fecha (consultando la tabla de control envios_agenda_medica).
3
Para cada médico calificado, recopila de forma ordenada todas sus citas del día de mañana (Paciente, Horario exacto de Inicio y Fin, Estado y Motivo de la Consulta).
4
Genera una plantilla de correo electrónico HTML dinámica con el recuento total de pacientes programados y una tabla detallada con los horarios.
5
Envía la agenda por correo al email del profesional.
6
Registra un renglón en la tabla envios_agenda_medica para ese médico y esa fecha. Esto asegura que el aviso se envíe exactamente una vez durante la franja de las 20:00 hs.

Módulo 1: Gestión de Pacientes

Centraliza la base de datos demográfica e información clínica general

A. Flujo de Procesos (CRUD)

C Crear
  • El administrativo completa el formulario de Paciente.
  • El sistema normaliza automáticamente el teléfono celular agregando el prefijo internacional argentino (549).
  • Se vincula al paciente con una Obra Social y se introduce su Número de Afiliado.
  • Se registran campos de alerta médica como Alergias, Dirección y Teléfono de Emergencia.
R Leer
  • Filtrar y buscar pacientes por DNI o por Nombre / Apellido.
  • Al ingresar a la ficha, si existen datos en el campo "Alergias", la pantalla muestra un recuadro de aviso destacado en color rojo.
U Actualizar
Permite corregir datos demográficos, cambios de obra social, nuevos contactos de emergencia o actualizar la lista de alergias.
D Eliminar
⚠️ Excepción Crítica: Un paciente no puede ser borrado físicamente si posee turnos agendados o registros en su historia clínica. En lugar de un borrado permanente, el sistema restringe o inactiva los registros manteniendo la coherencia histórica.

B. Reglas de Negocio

DNI Único: No se permite registrar a dos pacientes con el mismo número de DNI.
Validación de Email: El campo de correo electrónico debe seguir un patrón formal (nombre@dominio.com) para evitar errores en el Scheduler de recordatorios.

Módulo 2: Gestión de Profesionales y Horarios

Administra el equipo de salud, sus comisiones y grilla de atención semanal

A. Flujo de Procesos (CRUD)

C Crear
  • Se ingresa la especialidad, número de matrícula y el porcentaje de retención para la clínica.
  • El sistema requiere ingresar los horarios semanales mediante una grilla interactiva (ej: Lunes de 09:00 a 14:00).
  • Automatización: Al confirmar el alta del médico, el sistema crea automáticamente una cuenta de usuario con perfil MEDICO, estableciendo una contraseña temporal (su número de documento) y activando la bandera de cambio de contraseña obligatorio.
R Leer
Listado de médicos activos y visualización de sus turnos disponibles en el calendario.
U Actualizar
Permite actualizar datos demográficos, modificar el porcentaje de retención para nuevas consultas y rediseñar su grilla de horarios semanales.
D Eliminar
Un médico no se elimina físicamente si posee registros históricos de turnos o liquidaciones, manteniéndose su registro para auditoría histórica de pagos.

B. Reglas de Negocio

Horarios Consistentes: No se pueden guardar horarios con hora de inicio mayor o igual a la hora de fin.
Matrícula y CUIT únicos: Previene duplicidades de profesionales en el centro de salud.

Módulo 3: Agenda y Reservas de Turnos

Coordinación física de citas médicas cruzando disponibilidad del médico con requerimientos del paciente

A. Flujo de Procesos (CRUD)

C Crear
  • Se selecciona el médico, la fecha y se eligen horarios del catálogo de rangos libres de su agenda semanal.
  • El sistema inicializa la cita en estado Pendiente o Confirmado.
R Leer
Panel visual de turnos tipo calendario. Permite filtros por médico para ver las horas ocupadas y libres.
U Actualizar
Los turnos transicionan de estado durante el día:
Pendiente → Confirmado → Completado o Cancelado
D Cancelar
El administrativo cancela el turno, liberando inmediatamente el espacio en la grilla horaria para que pueda ser reservado por otro paciente.

B. Reglas de Negocio

Prevención de Superposiciones: El sistema impide agendar dos turnos al mismo tiempo para el mismo médico.
Fuera de Rango: No se pueden agendar turnos fuera de los días y horarios declarados de atención del profesional.

Módulo 4: Control de Caja Diaria

Módulo contable esencial para auditoría física de ingresos diarios en secretaría

A. Flujo de Procesos

Apertura
Al inicio del día laboral, el administrativo debe abrir la caja indicando el saldo físico de apertura (dinero disponible para dar vueltos, ej: $5.000). El estado de la caja pasa a Abierta.
Cobros
Cada vez que un paciente asiste a un turno, el administrativo registra el pago seleccionando el método de cobro (Efectivo, Transferencia, Tarjeta). El sistema suma automáticamente el monto a monto_cierre_esperado.
Cierre
  • Al finalizar el día, el operador realiza un conteo físico e ingresa el total en monto_cierre_real.
  • El sistema computa automáticamente la Diferencia de Caja (Cierre Real − Cierre Esperado).
  • Guarda las firmas de auditoría (Usuario de Apertura, Usuario de Cierre y sus respectivas fechas y horas exactas).
  • Cambia el estado de la caja a Cerrada.

B. Reglas de Negocio

Flujo Bloqueado: El sistema prohíbe registrar cobros o pagos de turnos si no existe una caja del día abierta.
Caja Única por Día: No se puede tener más de una caja abierta al mismo tiempo para la fecha en curso.
Caja Cerrada Inmutable: Una vez que una caja diaria se declara como Cerrada, no admite mutaciones o inserción de nuevos pagos.

Módulo 5: Liquidación de Honorarios Médicos

Cierres financieros para retribuir a los profesionales de la salud

A. Flujo de Procesos

C Procesar
  • El administrador selecciona un rango de fechas y un médico en particular.
  • El sistema extrae todos los turnos completados y cobrados en ese periodo.
  • Aplica los porcentajes de retención congelados en cada pago (guardados en la tabla pagos en el campo porcentaje_retencion).
  • Computa el monto bruto, la retención de la clínica y el neto que le corresponde cobrar al médico.
R Reportes
Muestra una planilla resumen interactiva con el detalle de las sumas a liquidar, facilitando la generación del pago físico o transferencia.

B. Regla Clave

🔒 Congelamiento de Condiciones: La retención copiada del perfil del profesional se guarda físicamente en la fila del pago. Si la clínica decide modificar la comisión de un médico de 20% a 25% el día de hoy, los turnos cobrados la semana pasada a tasa de 20% mantendrán sus comisiones intactas, evitando recálculos financieros retroactivos incorrectos.

Módulo 6: Historia Clínica Digital

Fichero médico privado reservado exclusivamente para el personal de salud

A. Flujo de Procesos (CRUD)

C Crear
  • El médico abre la ficha clínica del paciente durante la consulta e ingresa: Motivo de consulta, Evolución (síntomas, examen físico, notas), Diagnóstico oficial y Tratamiento prescrito.
  • Puede adjuntar archivos médicos (estudios en PDF, imágenes radiológicas) a la ficha del paciente.
R Leer
El médico puede visualizar la línea de tiempo de todas las evoluciones previas redactadas por él u otros profesionales de la clínica.
U Actualizar
Permite editar o agregar notas complementarias en caso de correcciones clínicas inmediatas.

B. Seguridad de Acceso y Privacidad

Exclusión de Roles: Los usuarios administrativos y de recepción no tienen acceso al módulo de Historia Clínica. Si intentan ingresar a una URL clínica, el sistema los redirige de inmediato bloqueando la consulta.
Permisos Compartidos (Acceso Invitado): A nivel de base de datos, la tabla Permisos_Historial permite autorizar a un profesional invitado a visualizar una ficha médica específica para interconsultas rápidas, garantizando confidencialidad.

Módulo 7: Gestión de Usuarios y Seguridad

Administra cuentas de acceso, roles y políticas estrictas de control de contraseñas

A. Flujo de Procesos y Alta de Usuarios

Alta Manual
  • El administrador crea una cuenta desde el panel de usuarios mediante el formulario correspondiente.
  • El sistema ejecuta el stored procedure sp_CreateUsuario que comprueba que ni el username ni el email estén previamente registrados. En caso de duplicidad, interrumpe la transacción y lanza un error personalizado (THROW 51000).
Alta Automática

Al registrar un nuevo médico, el sistema genera su cuenta de acceso de manera completamente automática bajo una misma transacción SQL:

  • Nombre de Usuario: Primera letra del nombre + apellido en minúsculas (ej: Juan Pérez → jperez). Si existe, un bucle WHILE incrementa un contador (jperez1, jperez2…).
  • Email: Dirección temporal ficticia con el patrón username@MedCloud.local.
  • Contraseña Inicial: Número de DNI del profesional.
  • Cambio Obligatorio: Se activa el flag debe_cambiar_pass = 1.
Inactivación
Se promueve la inactivación lógica del usuario estableciendo el campo activo = 0 para impedir el login sin perder el rastro de auditoría en el sistema. El borrado físico está disponible pero restringido por restricciones de clave foránea en la base de datos.

B. Gestión de Contraseñas y Seguridad

Políticas de Contraseña en Primer Acceso: Cuando un usuario inicia sesión y tiene el flag debe_cambiar_pass = 1, el frontend redirige de forma obligatoria a un panel de cambio de contraseña, impidiendo cualquier otra operación. Al guardar la nueva contraseña, el sistema valida que no coincida con la actual mediante LTRIM/RTRIM. Si coinciden, interrumpe el proceso lanzando el error 51000: 'La nueva contraseña no puede ser igual a la anterior.'.
Flujo de Recuperación de Contraseña (Forgot Password):
  1. Solicitud: El usuario proporciona su email. El sistema genera un token criptográfico aleatorio de 32 bytes (64 caracteres hex) con expiración de 1 hora y despacha un email HTML mediante Nodemailer.
  2. Mitigación de Enumeración: El sistema devuelve siempre el mismo mensaje genérico al cliente, tanto si el email existe como si no, para evitar la fuga de información sobre cuentas registradas.
  3. Validación del Token: Valida que el token exista, pertenezca a un usuario activo, no haya sido usado (usado = 0) y que la fecha de expiración sea posterior a la actual.
  4. Aplicación del Cambio: Actualiza la contraseña, pone a 0 el flag debe_cambiar_pass, marca el token como usado y anula cualquier otro token pendiente para ese usuario.
